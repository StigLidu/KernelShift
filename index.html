KernelShift

Benchmarking Kernel Optimization Across Evolving Hardware

Shuaiwei Huang1*, Weihua Du1*, Allen Wu1*, Ivan Fox2, Manupa Karunaratne2, Yiming Yang1, Sean Welleck11Carnegie Mellon University · 2Arm Ltd. · *Equal contribution

Each new generation of Arm processors adds instruction-set extensions, shifting over time, and the fastest code has to be rewritten to use them. KernelShift gives agents 101 real optimization tasks from four open-source libraries and runs their code on the real processors. We provide a task collection pipeline and an evaluation framework for kernel optimization on evolving hardware, and show that agents beat library code on established extensions but still struggle with newer ones.

Motivation

New hardware changes how fast code has to be written

Arm keeps adding instruction-set extensions. Some add new instructions; others, like SME2, bring a new programming model, so fast code has to be reorganized, not just recompiled. Expert libraries take time to catch up with each one, and existing kernel benchmarks test a fixed target rather than a sequence of hardware changes. KernelShift asks whether coding agents can make this shift.

Neon
Every 64-bit Arm processor

The base instruction set. Each instruction handles a few numbers at once.

Intrinsics work on fixed 128-bit registers (4 floats).
SVE
AWS Graviton3 (2022)

New instructions: longer rows, and one piece of code works for any row length.

Intrinsics work on vectors of any length, from 128 to 2048 bits.
SVE2
AWS Graviton4 (2024)

More instructions, same programming model: more kinds of operations on the same rows.

Same intrinsics style as SVE, with more operations.
SME2
Apple M4 (2024)

A new programming model: compute on a grid of numbers in a special mode, so code has to be organized differently.

Intrinsics work on 2D tiles.

Agents pick up new instructions well. When the programming model changes, they fall behind.

Task collection pipeline

kgen: an agent builds the tasks, people check them

kgen is our command-line toolkit for turning code from open-source libraries into benchmark tasks, with skills for agents to follow step by step. A coding agent runs it; people make the few decisions and verify the result.

    Evaluation framework

    Any agent, measured on the real processor

    Agents connect to the KernelShift server. Every agent gets the same toolkit, and each call runs on a machine with the target processor.

    Correctness

    Every test input must pass

    Code is timed only after it gives the right answer on every test input of the task.

    Timing

    Same machine, same clock

    The agent's code and the expert code are timed on the same machine, the same way.

    Integrity

    One core, no shortcuts

    Each run gets one core and its own process.

    Key results

    Strong on familiar extensions, weak on a new programming model

    Scores below compare the agent's code with the code the library ships for that processor.

    Established extension (SVE)

    Agents beat the code popular libraries ship

    The best tested agent (GLM-5.3 with nanobot) is 2.7× faster than ncnn's own code, and the best tested agents are about 1.95× faster on llama.cpp and 1.56× on Arm SIMD Loops. Arm's hand-tuned KleidiAI code is still ahead. A compiler on its own reaches at most half the library's speed.

    Real LLM inference

    The gains carry over to running an LLM

    We put agent-written code for the matrix multiplications of two LLMs into llama.cpp on AWS Graviton4. Compared with the original llama.cpp, prompt processing gets 1.3 to 1.6 times faster, while token generation stays about as fast as before (0.94 to 1.06 times).

    Moving to a newer extension (SVE → SME2)

    A new programming model costs far more than new instructions

    Each model's speed relative to the expert code on KleidiAI's kernels, first on SVE, then on SME2, which brings a new programming model. All four models drop, Claude Opus 4.8 the least (0.85× to 0.68×) and GLM-5.3 the most (0.78× to 0.15×).

    Get started

    Try one task locally, or run an agent in one command

    Install, then test and time one task
    # Python 3.12+ and clang++
git clone https://github.com/ArtificialRay/KernelShift
cd KernelShift
pip install -r requirements.txt
hf download arm-bench/arm-bench-trace \
    --repo-type dataset --local-dir bench-trace

python -m bench.cli bench --dataset simd-loop --isa sve \
    --definition loop_001 --solution reference_loop_001

    # starts the instance, runs the agent, copies results back
